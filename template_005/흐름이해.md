## 📌 전체 동작 흐름 요약

```
GET / POST → Router::path()에 저장
→ handleRequest() 실행
→ URL 정규식 매칭
→ 등록된 function 자동 실행
```

---

## 1️⃣ 라우트 등록 – GET/POST

```php
GET("/users/{id}", function($id){
    ...
});
```

* 해당 URL로 접근했을 때 실행할 함수를 등록하는 단계
* 하지만 **GET/POST는 실행이 아니라 "등록"만 함**
* 내부적으로 `Router::path()` 호출됨

---

## 2️⃣ Router::path() – 매핑 저장

```php
static function path($method,$uri,$handler){
    $uri = preg_replace('#\{(.*?)\}#','([^\/]+)',$uri);
    self::$routes[] = [$method,"#^$uri$#",$handler];
}
```

| 기능                     | 설명                     |
| ---------------------- | ---------------------- |
| `{id}` → `([^\/]+)` 변환 | URL 변수 매칭 가능하도록 정규식 치환 |
| `$routes[]`에 push      | 모든 라우트 저장              |

저장 후 라우트 구조 예:

```
[
  ['GET',  '#^/users/([^/]+)$#', function($id) {...}],
  ['POST', '#^/users/profile/([^/]+)$#', ...],
]
```

---

## 3️⃣ Router::handleRequest() – 요청 처리 핵심

```php
Router::handleRequest();
```

실행되면 하는 일:

1. 현재 요청 URL과 Method(GET/POST) 확인
2. 등록된 routes와 하나씩 비교
3. 정규식 매칭 성공 → 해당 handler 실행

```php
if (preg_match($uri,$REQUEST_URI,$matches)) {
    array_shift($matches);
    return call_user_func_array($handler,$matches);
}
```

---

## 4️⃣ 실행 결과 예시

요청:

```
GET /users/20
```

실행 흐름:

```
GET()        → path()로 라우트 저장
브라우저 요청 → handleRequest 실행
정규식 매칭   → /users/{id} 적중
id=20 전달    → function(20) 실행!
```

---

## 🍽 이해 비유

| 코드                   | 비유               |
| -------------------- | ---------------- |
| GET("/users/{id}")   | 메뉴판에 요리 추가       |
| path()               | 메뉴와 조리법 저장       |
| handleRequest()      | 손님이 주문하면 메뉴 선택   |
| call_user_func_array | 재료(id)를 넣어 요리 실행 |

---

## 🔥 최종 핵심 5줄 요약

1. GET/POST는 라우트 등록용
2. path()가 URL 패턴과 실행함수 저장
3. handleRequest()가 실제 URL 매칭
4. 매칭 시 call_user_func_array로 함수 실행
5. {id} 같은 URL 파라미터도 자동 전달됨
